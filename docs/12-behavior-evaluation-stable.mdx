# 성능 평가 (2) - 차선 변경, 급감속, 정체 지속 시간 분석

지난 실험에서는 PPO 에이전트의 침투율을 0%, 5%, 10%로 나누어 평균 속도와 throughput을 비교하였다. 그 결과 PPO 에이전트가 투입된 조건에서 throughput이 증가하는 경향은 확인할 수 있었다.

하지만 throughput이 증가했다고 해서 곧바로 교통 흐름이 안정적으로 개선되었다고 말할 수는 없다. 차량이 더 많이 통과하더라도, 그 과정에서 차선 변경이 잦아지거나 급감속이 늘어나면 오히려 후방 차량의 불안정성을 키울 수 있다.

따라서 이번 Week 12에서는 평균 속도와 throughput을 넘어서, PPO 에이전트가 실제로 도로 흐름을 안정화하는지 확인하기 위해 다음 세 가지 행동 지표를 추가로 측정하였다.

```text
1. 차선 변경 횟수
2. 급감속 횟수
3. 특정 구간 정체 지속 시간
```

이번 실험의 핵심 가설은 다음과 같다.

```text
PPO 에이전트가 투입되면
전체 2차선 도로에서 불필요한 차선 변경과 급감속이 줄고,
특정 구간의 정체 지속 시간이 감소할 것이다.
```

---

## 1. 평가 목표

이번 평가의 목표는 PPO 에이전트가 단순히 더 많은 차량을 통과시키는지를 확인하는 것이 아니다. 더 중요한 것은 **교통 흐름을 안정적으로 만드는지**이다.

이를 위해 다음 지표를 비교하였다.

```text
평가 지표:
- avg_speed: 전체 차량 평균 속도
- throughput: 기준 지점을 통과한 차량 수
- lane_change_count: 전체 차량의 차선 변경 횟수
- hard_brake_count: 급감속 발생 횟수
- congestion_time_sec: 특정 구간의 정체 지속 시간
- crashed_count: 충돌 차량 수
```

침투율 조건은 이전과 동일하게 0%, 5%, 10%로 설정하였다.

```text
0%  → Baseline, PPO 에이전트 없음
5%  → 전체 차량 중 일부를 PPO 정책으로 제어
10% → PPO 에이전트 비율을 더 높인 조건
```

각 조건에서는 10개의 episode를 반복 실행하였다.

## 3. 행동 지표 계산 방식

### 3-1. 차선 변경 횟수

차선 변경 횟수는 각 차량의 이전 차선과 현재 차선을 비교하여 계산하였다.

```text
이전 lane_index != 현재 lane_index
→ 차선 변경 1회로 카운트
```

이 지표는 PPO 에이전트가 불필요하게 좌우 차선을 반복적으로 이동하는지 확인하기 위한 값이다. 차선 변경이 너무 많으면 주변 차량의 감속과 정체 파동을 유발할 수 있다.

---

### 3-2. 급감속 횟수

급감속은 이전 step의 속도와 현재 step의 속도 차이를 이용해 계산하였다.

```text
deceleration = (previous_speed - current_speed) / dt
```

이번 평가에서는 감속도가 기준값 이상이면 급감속으로 판단하였다.

```text
hard_brake_decel_threshold = 3.0 m/s²
```

즉, 차량이 짧은 시간 안에 급격히 속도를 줄이면 `hard_brake_count`가 증가한다.

---

### 3-3. 정체 지속 시간

정체 시간은 특정 도로 구간 안에 있는 차량들의 평균 속도를 기준으로 계산하였다.

```text
측정 구간:
x = 200m ~ 500m

정체 기준:
구간 내 차량 평균 속도 < 10.0 m/s
```

해당 조건을 만족하는 step의 개수를 세고, 이를 초 단위로 변환하였다.

```text
congestion_time_sec = congestion_steps × (1 / policy_frequency)
```

다만 이번 실험에서는 대부분의 episode에서 정체 시간이 0초로 측정되었다. 따라서 현재의 정체 판단 기준만으로는 정체 완화 효과를 충분히 비교하기 어렵다는 한계가 있었다.

## 4. 초기 Week12 행동 지표 평가 결과

먼저 기존 tuned 모델을 사용하여 행동 지표를 평가하였다. 이 평가에서는 10% 침투율 조건에서 평균 속도와 급감속 측면에서 일부 긍정적인 변화가 있었지만, 차선 변경과 crash 지표는 증가하였다.

분석 결과는 다음과 같았다.

```text
0%  → baseline
5%  → not_supported
10% → partially_supported
```

10% 조건에서는 급감속 횟수가 Baseline보다 감소하는 구간이 있었기 때문에 `partially_supported`로 해석할 수 있었다. 그러나 5% 조건에서는 평균 속도가 낮아지고 급감속이 증가했으며, 5%와 10% 조건 모두에서 차선 변경 횟수가 증가하였다.

따라서 초기 Week12 평가만으로는 “PPO 에이전트가 차선 변경과 급감속을 줄인다”는 가설을 충분히 지지하기 어려웠다.

## 5. 안정성 우선 재튜닝

초기 평가 결과를 바탕으로, 추가 튜닝에서는 throughput을 더 높이는 것보다 안정성 지표를 우선적으로 개선하는 방향을 선택하였다.

기존 결과에서 가장 큰 문제는 다음과 같았다.

```text
문제점:
- PPO 침투율이 증가할수록 차선 변경 증가
- 급감속 횟수 증가
- crash 지표 증가
- throughput 증가는 있었지만 안정성 악화 동반
```

따라서 이번 튜닝에서는 차선 변경, 급감속, 충돌에 대한 페널티를 더 강화하였다.

```python
reward_config = {
    "w_speed": 1.2,
    "w_col": 10.0,
    "w_lane": 0.8,
    "w_global": 1.2,
    "w_hard_brake": 2.0,
    "target_speed": 23.0,
    "hard_brake_decel_threshold": 2.5,
}
```

각 가중치의 의미는 다음과 같다.

```text
w_col = 10.0
→ 충돌 억제 강화

w_lane = 0.8
→ 차선 변경 페널티 강화

w_hard_brake = 2.0
→ 급감속 페널티 강화

w_global = 1.2
→ throughput만 과도하게 높이려는 경향 완화

w_speed = 1.2
→ 속도 보상은 유지하되, 무리한 속도 추구는 완화

target_speed = 23.0
→ 안정적인 주행을 유도하기 위해 목표 속도 완화

hard_brake_decel_threshold = 2.5
→ 급감속을 더 민감하게 감지
```

튜닝 학습은 `train_week12_stable_ppo.py`를 통해 진행하였고, 최종 모델은 다음 이름으로 저장하였다.

```text
models/ppo_2lane_week12_stable_final.zip
```

## 7. Throughput 결과 해석

먼저 throughput만 보면 PPO 에이전트 투입 효과는 분명히 나타났다.

```text
throughput 변화:
0%  → 약 2.80
5%  → 약 6.30
10% → 약 6.70
```

5%와 10% 조건 모두 Baseline보다 더 많은 차량이 기준 지점을 통과하였다. 즉, PPO 에이전트는 교통 처리량을 증가시키는 방향으로는 어느 정도 작동하였다.

그러나 이번 Week12 실험의 핵심은 throughput 증가가 아니라 **안정성 지표 개선**이었다. 따라서 throughput이 증가했더라도, 차선 변경과 급감속이 함께 증가한다면 긍정적인 결과라고 보기 어렵다.

---

## 8. 차선 변경 결과 해석

차선 변경 횟수는 PPO 에이전트가 투입될수록 증가하였다.

```text
lane_changes 변화:
0%  → 약 1.00
5%  → 약 4.00
10% → 약 6.90
```

5% 조건에서는 Baseline 대비 약 4배, 10% 조건에서는 약 6.9배 수준으로 차선 변경이 증가하였다.

분석 결과에서도 차선 변경 감소율은 음수로 계산되었다.

```text
lane_change_reduction_pct:
5%  → -300.0%
10% → -590.0%
```

이는 차선 변경이 감소한 것이 아니라, 오히려 크게 증가했다는 의미이다.

따라서 차선 변경 감소 가설은 지지되지 않았다.

---

## 9. 급감속 결과 해석

급감속 횟수 역시 PPO 에이전트가 투입된 조건에서 증가하였다.

```text
hard_brakes 변화:
0%  → 약 395.80
5%  → 약 458.30
10% → 약 466.80
```

급감속 페널티를 reward에 추가했음에도 불구하고, 다중 에이전트 평가 조건에서는 급감속 억제 효과가 충분히 나타나지 않았다.

이는 단일 controlled vehicle 기준으로 학습된 정책을 여러 PPO 차량에 동시에 적용했을 때, 차량 간 상호작용이 예상보다 불안정하게 발생했기 때문으로 해석할 수 있다.

---

## 10. Crash 결과 해석

crash 지표도 침투율이 높아질수록 증가하였다.

```text
crashed 변화:
0%  → 약 2.00
5%  → 약 3.40
10% → 약 7.20
```

안정성 우선 튜닝에서 충돌 페널티를 강화했지만, 5%와 10% 평가 조건에서는 Baseline보다 높은 crash 지표가 나타났다.

이 결과는 현재 정책이 다중 PPO 차량 환경에서 안정적으로 작동하지 못하고 있음을 보여준다.

---

## 11. 정체 지속 시간 결과 해석

정체 지속 시간은 모든 조건에서 대부분 0초로 측정되었다.

```text
congestion_time:
0%  → 0.00s
5%  → 0.00s
10% → 0.00s
```

따라서 이번 설정에서는 정체 지속 시간 감소 여부를 충분히 비교하기 어려웠다.

가능한 원인은 다음과 같다.

```text
1. 실제로 해당 구간에서 정체 기준을 만족하는 상황이 거의 발생하지 않음
2. congestion_speed_threshold가 너무 낮게 설정됨
3. congestion_x_min, congestion_x_max 구간이 정체가 발생하는 위치와 맞지 않음
```

이후 실험에서는 정체 판단 기준을 더 민감하게 조정하거나, 정체 측정 구간을 다시 설정할 필요가 있다.

## 14. 결과 해석

이번 실험에서 가장 중요한 결론은, 단순한 reward weight 조정만으로는 문제를 해결하기 어렵다는 점이다.

현재 PPO 정책은 기본적으로 단일 controlled vehicle 환경에서 학습되었다. 하지만 평가는 5%, 10% 침투율 조건에서 여러 PPO 차량을 동시에 투입하는 구조이다.

```text
학습 환경:
- PPO controlled vehicle 1대 중심
- 단일 에이전트 정책 학습

평가 환경:
- PPO controlled vehicle 여러 대
- 같은 정책을 여러 차량에 동시 적용
- PPO 차량 간 상호작용 발생
```

단일 에이전트 환경에서 학습한 정책이 여러 차량에 동시에 복제되면, 차량 간 행동이 서로 간섭할 수 있다. 그 결과 차선 변경과 급감속, crash가 증가할 수 있다.

이번 결과는 이러한 단일 에이전트 정책의 한계를 보여준다.

## 15. 다음 단계

다음 단계에서는 2차선 시공간 다이어그램을 생성하여, 학습 에이전트가 도로 정체 흐름에 미친 영향을 시각적으로 분석한다. 기존 평가는 평균 속도, throughput, 차선 변경, 급감속처럼 수치 중심으로 진행했지만, 이번에는 차량 궤적을 시간-공간 축으로 표현하여 정체 파동이 실제로 줄어들었는지 확인한다.

```text
다음 실험 주제:
2차선 시공간 다이어그램 생성 및 실험 보고서 작성
```

Python `matplotlib`를 사용해 각 차량의 주행 궤적을 차선별로 분리하여 시공간 다이어그램으로 시각화한다. 이를 통해 특정 구간에서 차량들이 밀집되거나 속도가 급격히 낮아지는 구간을 이미지로 확인할 수 있다.

또한 학습된 PPO 에이전트 투입 전후의 결과를 비교하여, 정체가 퍼지는 핵심 시각 자료를 추출한다. 이 이미지를 기반으로 실험 보고서에서는 차선 변경 감소, 급감속 감소, 정체 지속 시간 단축 여부를 종합적으로 해석한다.

```text
기대 결과물:
- 1차선/2차선 차량 궤적 시공간 다이어그램
- 정체 파동 시각 자료
- 실험 결과 요약 보고서
```
