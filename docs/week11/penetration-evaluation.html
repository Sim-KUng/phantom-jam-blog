학습 에이전트 성능 평가 (1) - 침투율별 통행량 지표 비교

지난 주차까지는 PPO 에이전트를 학습시키고, TensorBoard를 통해 학습 과정의 reward, episode length, collision rate, lane change ratio 등을 모니터링했다. 이번 주차부터는 학습 과정 자체가 아니라, 학습된 에이전트가 실제로 교통 흐름을 개선하는지 평가하는 단계로 넘어간다.

이번 실험의 핵심은 자율주행 에이전트 침투율(Penetration Rate) 을 다르게 설정했을 때, 전체 교통 흐름 지표가 어떻게 변하는지 비교하는 것이다. 침투율은 전체 차량 중 PPO 정책을 따르는 차량의 비율을 의미한다.

침투율 0%  → Baseline, PPO 에이전트 없음
침투율 5%  → 전체 차량 중 일부만 PPO 정책 사용
침투율 10% → PPO 정책 차량 비율 증가

이번 주차에서는 침투율을 0%, 5%, 10%로 나누어 평가하고, 각 조건에서 전체 차량의 평균 속도와 통과 차량 수(Throughput)를 CSV로 저장했다.

💡 info 이번 주차의 핵심 목표 학습된 PPO 모델을 평가용 시뮬레이터에 로드한 뒤, 자율주행 에이전트 침투율을 0%, 5%, 10%로 변화시키며 평균 속도와 통행량을 정량적으로 비교한다.

1. 왜 침투율별 평가가 필요한가?​

강화학습 에이전트가 단일 차량으로 잘 움직인다고 해서, 실제 교통 흐름 전체를 개선한다고 말할 수는 없다. 특히 유령 정체 완화 문제에서는 한 대의 차량이 빠르게 달리는 것보다, 여러 차량과 상호작용했을 때 전체 흐름이 안정되는지가 더 중요하다.

따라서 이번 평가에서는 PPO 에이전트를 도로에 조금씩 더 많이 투입하면서 다음 질문을 확인했다.

1. PPO 에이전트가 없을 때의 Baseline 성능은 어느 정도인가?
2. PPO 에이전트를 5%만 투입해도 평균 속도나 통행량이 개선되는가?
3. PPO 에이전트를 10%로 늘리면 성능이 더 좋아지는가?
4. 침투율 증가가 오히려 교통 흐름을 불안정하게 만들지는 않는가?

이번 실험은 최종 성능 검증이라기보다는, 학습된 정책이 혼합 교통 환경에서 어떤 경향을 보이는지 확인하는 1차 평가에 가깝다.

2. 평가 시나리오 구성​

이번 평가에서는 차량 수를 60대로 두고, 침투율에 따라 PPO 제어 차량 수를 다르게 설정했다.

전체 차량 수: 60대

0%  조건 → PPO 차량 0대
5%  조건 → PPO 차량 약 3대
10% 조건 → PPO 차량 약 6대

단, highway-env 구조상 controlled vehicle을 완전히 0대로 두기 어렵기 때문에, 0% Baseline에서는 최소 controlled vehicle 1대를 유지하되 PPO 모델을 사용하지 않고 IDLE action을 적용하는 방식으로 처리했다.

0% Baseline:
PPO model.predict() 사용 안 함
action = 1, 즉 IDLE action 사용

5%, 10% 조건:
PPO model.predict() 사용
각 controlled vehicle의 observation에 대해 action 예측

5. 시뮬레이터 구동 방식​

이번 평가에서 말하는 "시뮬레이터 구동"은 별도의 프로그램을 실행한다는 뜻이 아니다. Python 코드 안에서 highway-v0 환경을 생성하고, 매 step마다 PPO 모델이 action을 예측한 뒤, env.step(action)을 호출하여 시뮬레이션을 진행한다는 의미이다.

env = gym.make("highway-v0", render_mode=None)

이 코드가 highway-env 시뮬레이터를 생성하는 부분이다. 평가에서는 여러 episode를 빠르게 반복해야 하므로 화면을 띄우지 않는 render_mode=None을 사용했다.

시뮬레이션은 다음 구조로 진행된다.

obs, info = env.reset()

while not (terminated or truncated):
    action = model.predict(obs, deterministic=True)
    obs, reward, terminated, truncated, info = env.step(action)

즉, PPO 모델이 현재 도로 상태를 보고 action을 선택하고, 그 action이 도로 환경에 적용되면서 차량들이 한 step씩 이동한다.

6. 다중 에이전트 평가 구조 수정​

처음 5%, 10% 조건을 평가할 때 다음과 같은 observation shape 오류가 발생했다.

ValueError:
Unexpected observation shape (5,)
please use (15, 5) or (n_env, 15, 5)

원인은 5%, 10% 조건에서 controlled vehicle이 여러 대가 되는데, 기존 observation/action 설정은 단일 에이전트 구조였기 때문이다. 즉, 여러 PPO 차량을 동시에 평가하려면 각 controlled vehicle에 대한 observation과 action을 따로 처리해야 한다.

그래서 5%, 10% 조건에서는 다음 구조를 사용하도록 수정했다.

MultiAgentObservation
MultiAgentAction

수정한 환경 설정의 핵심은 다음과 같다.

observation_config = {
    "type": "MultiAgentObservation",
    "observation_config": {
        "type": "Kinematics",
        "features": ["presence", "x", "y", "vx", "vy"],
        "vehicles_count": 15,
        "normalize": True,
        "absolute": False,
        "order": "sorted",
    },
}

action_config = {
    "type": "MultiAgentAction",
    "action_config": {
        "type": "DiscreteMetaAction",
    },
}

이후 각 controlled vehicle의 observation을 하나씩 PPO 모델에 넣고, 예측된 action들을 tuple 형태로 묶어 env.step()에 전달했다.

actions = []

for single_obs in obs:
    action, _ = model.predict(single_obs, deterministic=True)
    actions.append(int(action))

return tuple(actions)

이렇게 수정한 뒤 5%, 10% 침투율 조건도 정상적으로 평가할 수 있었다.

7. 평가 지표​

이번 실험에서 사용한 핵심 지표는 세 가지이다.

1. Average Speed
2. Throughput
3. Crashed Count

7-1. Average Speed​

avg_speed는 한 episode 동안 도로 위 전체 차량의 평균 속도를 의미한다. 이 값은 차량들이 전체적으로 얼마나 빠르게 움직였는지를 보여준다.

avg_speed가 높음
→ 차량 흐름이 상대적으로 빠름

avg_speed가 낮음
→ 감속, 정체, 상호작용 불안정 가능성

7-2. Throughput​

throughput은 일정 시간 동안 특정 지점을 통과한 차량 수를 의미한다.

throughput = 기준 지점 x를 통과한 차량 수

이번 코드에서는 차량의 x 좌표가 throughput_x를 처음 넘어가는 순간을 통과로 간주하고 1대로 카운트했다.

차량이 기준 지점 통과
→ throughput + 1

평균 속도만 보면 교통 효율을 정확히 판단하기 어렵기 때문에, throughput을 함께 확인해야 한다. 평균 속도가 높아도 실제로 통과한 차량 수가 적다면 교통 처리량이 좋다고 보기 어렵다.

7-3. Crashed Count​

crashed_count는 episode 동안 충돌한 차량 수를 기록하기 위한 지표이다. 처음에는 매 step마다 crashed 상태를 누적해 같은 차량이 여러 번 카운트되는 문제가 있었다. 이 경우 차량 수가 60대인데 crashed 값이 100 이상으로 나오는 비정상적인 결과가 발생할 수 있다.

그래서 이후에는 차량 ID를 기준으로 고유 충돌 차량만 세도록 수정했다.

crashed_vehicle_ids = set()

for vehicle in env.unwrapped.road.vehicles:
    if getattr(vehicle, "crashed", False):
        crashed_vehicle_ids.add(id(vehicle))

crashed_count = len(crashed_vehicle_ids)

이렇게 수정한 뒤 재평가에서는 모든 episode에서 crashed=0으로 안정적인 결과가 나왔다.

10. Pandas를 이용한 요약 분석​

평가 CSV를 저장한 뒤, analyze_week11_results.py를 이용해 침투율별 평균값과 표준편차를 계산했다.

분석 결과는 다음 파일로 저장된다.

분석 스크립트에서는 groupby()를 이용해 침투율별 통계를 계산했다.

summary = (
    df.groupby("penetration_rate")
    .agg(
        episodes=("episode", "count"),
        controlled_count_mean=("controlled_count", "mean"),
        avg_speed_mean=("avg_speed", "mean"),
        avg_speed_std=("avg_speed", "std"),
        throughput_mean=("throughput", "mean"),
        throughput_std=("throughput", "std"),
        crashed_count_mean=("crashed_count", "mean"),
    )
    .reset_index()
)

이를 통해 0%, 5%, 10% 조건에서 평균 속도, throughput, 충돌 수를 한 번에 비교할 수 있다.

침투율별 평균값을 보여주는 막대 그래프는 전체 경향을 확인하기 위한 핵심 자료이고, episode별 선 그래프는 각 침투율 조건에서 성능이 얼마나 흔들리는지 확인하기 위한 보조 자료이다.

11-1. 침투율별 평균 속도 비교​

먼저 침투율별 전체 차량 평균 속도를 비교했다. 이 그래프는 PPO 에이전트의 비율이 증가했을 때 도로 전체 차량의 평균 속도가 개선되는지 확인하기 위한 지표이다.

침투율별 전체 차량 평균 속도 비교

평균 속도는 차량들이 전체적으로 얼마나 빠르게 움직였는지를 보여준다. 만약 PPO 에이전트가 정체 파동을 완화한다면 침투율이 증가할수록 평균 속도가 상승하는 흐름을 기대할 수 있다. 다만 이번 결과에서는 침투율 증가에 따른 평균 속도 향상이 일관적으로 나타나지는 않았다.

11-2. 침투율별 Throughput 비교​

다음으로 침투율별 throughput을 비교했다. Throughput은 일정 시간 동안 기준 지점을 통과한 차량 수를 의미하며, 실제 교통 처리량을 확인하기 위한 핵심 지표이다.

침투율별 통과 차량 수 비교

평균 속도만으로는 교통 효율을 완전히 판단하기 어렵다. 차량이 빠르게 움직이더라도 실제로 통과한 차량 수가 적으면 전체 처리량이 높다고 보기 어렵기 때문이다. 이번 실험에서는 5% 조건에서 일부 episode의 throughput이 크게 증가했지만, 10% 조건이 5%보다 일관되게 좋아지지는 않았다.

11-3. Episode별 평균 속도 변화​

침투율별 평균값만 보면 각 episode에서 성능이 얼마나 흔들렸는지 확인하기 어렵다. 따라서 episode별 평균 속도 변화도 함께 확인했다.

에피소드별 평균 속도 변화

이 그래프를 통해 같은 침투율 조건 안에서도 episode마다 평균 속도가 달라지는 것을 확인할 수 있다. 특히 강화학습 정책은 초기 평가 단계에서 특정 상황에는 잘 대응하지만, 다른 교통 초기 조건에서는 성능이 흔들릴 수 있다. 따라서 평균값뿐 아니라 episode별 변화도 함께 확인해야 한다.

11-4. Episode별 Throughput 변화​

마지막으로 episode별 throughput 변화를 확인했다. 이 그래프는 특정 침투율 조건에서 통과 차량 수가 안정적으로 증가하는지, 아니면 일부 episode에서만 일시적으로 높게 나타나는지 확인하기 위해 사용했다.

에피소드별 throughput 변화

이번 결과에서는 5% 조건에서 throughput이 크게 튀는 episode가 있었지만, 모든 episode에서 안정적으로 높은 값을 보인 것은 아니었다. 따라서 현재 PPO 정책은 교통 흐름 개선 가능성은 보이지만, 아직 침투율 증가에 따라 일관적으로 성능을 개선하는 단계까지 도달했다고 보기는 어렵다.

시각화 결과 해석:
평균 속도 그래프
→ 침투율 증가에 따른 속도 개선 여부 확인

throughput 그래프
→ 실제 통과 차량 수 증가 여부 확인

episode별 그래프
→ 성능이 안정적인지, 특정 episode에만 의존하는지 확인

12. 결과 해석​

이번 평가 결과는 다음과 같이 정리할 수 있다.

1. 침투율별 평가 파이프라인은 정상적으로 구축되었다.
2. PPO 모델을 평가용 스크립트에 로드하여 시뮬레이터를 자동 구동할 수 있었다.
3. 0%, 5%, 10% 조건 모두에서 충돌 없이 평가가 수행되었다.
4. 5% 조건에서는 일부 episode에서 throughput이 크게 증가했다.
5. 하지만 평균 속도와 throughput이 침투율 증가에 따라 일관되게 좋아지지는 않았다.

즉, 이번 결과는 PPO 에이전트가 교통 흐름 개선 가능성을 일부 보였지만, 아직 안정적으로 성능을 향상시키는 정책이라고 보기는 어렵다는 결론에 가깝다.

특히 5% 조건에서는 throughput이 높게 나온 episode가 있었지만, 평균 속도는 낮아지는 경우도 있었다. 이는 PPO 에이전트가 특정 상황에서는 차량 통과량을 늘릴 수 있지만, 전체적인 속도 흐름을 안정적으로 유지하는 데는 아직 부족하다는 의미일 수 있다.

10% 조건에서는 PPO 에이전트 수가 더 많아졌지만, throughput이 5%보다 일관적으로 증가하지 않았다. 이는 단일 에이전트 환경에서 학습한 정책을 여러 차량에 동시에 적용했을 때, 각 PPO 차량의 행동이 서로 간섭할 수 있음을 보여준다.

💡 info 1차 평가 결론 현재 PPO 정책은 충돌 없이 평가를 수행할 수 있을 정도의 안정성은 확보했지만, 침투율 증가에 따라 평균 속도와 throughput을 일관되게 개선하지는 못했다. 따라서 2차 보상 함수 튜닝과 추가 학습이 필요하다.

13. 2차 튜닝 방향​

1차 침투율 평가에서는 PPO 에이전트가 투입된 조건에서 throughput이 일부 증가하는 경향을 보였지만, 평균 속도는 침투율에 따라 일관되게 개선되지 않았다. 특히 5% 조건에서는 통과 차량 수가 증가하는 episode가 있었지만, 평균 속도가 Baseline보다 낮아지는 구간도 함께 나타났다.

따라서 2차 튜닝의 목표는 단순히 throughput만 높이는 것이 아니라, 충돌 없는 안정성을 유지하면서 평균 속도 저하를 줄이고, 통과 차량 수 증가 효과를 유지하는 것으로 설정하였다.

2차 튜닝 목표:
- crashed = 0 유지
- avg_speed 하락 방지
- throughput 증가 효과 유지
- 5%, 10% 침투율 조건에서 성능 편차 감소

기존 1차 튜닝에서는 후방 차량 흐름을 강조하기 위해 w_global 값을 크게 높였다. 그러나 이 경우 에이전트가 전체 흐름을 안정화하려는 방향으로는 학습되지만, 자기 차량의 속도 유지가 약해질 수 있다. 따라서 2차 튜닝에서는 속도 보상을 조금 더 강화하고, 후방 흐름 보상은 약간 낮추는 방향으로 조정하였다.

reward_config = {
    "w_speed": 1.5,
    "w_col": 6.0,
    "w_lane": 0.15,
    "w_global": 2.0,
    "target_speed": 25.0,
}

각 가중치 조정의 의미는 다음과 같다.

w_speed: 1.3 → 1.5
→ 평균 속도 유지 강화

w_col: 6.0 유지
→ 충돌 없는 안정성 유지

w_lane: 0.15 유지
→ 필요한 차선 변경은 허용

w_global: 2.2 → 2.0
→ 후방 흐름 보상은 유지하되, 속도 저하를 유발할 정도의 과도한 영향은 완화

이번 추가 학습은 기존에 학습된 ppo_2lane_week11_tuned_final 모델에서 이어서 진행하였다. 즉, 처음부터 다시 학습하는 것이 아니라 이미 어느 정도 안정적인 정책을 가진 모델을 기반으로, 보상 가중치를 조정한 뒤 추가 학습을 수행하였다.

model_path = "models/ppo_2lane_week11_tuned_final"

추가 학습 후에는 새로운 모델을 다음 이름으로 저장하였다.

final_model_path = "models/ppo_2lane_week11_tuned_v2_final"

14. 2차 튜닝 후 재평가​

2차 튜닝이 완료된 뒤, 동일한 평가 스크립트를 사용하여 침투율별 성능을 다시 측정하였다. 평가 조건은 이전과 동일하게 0%, 5%, 10% 세 가지 침투율로 구성하였다.

평가 조건:
- 0%: Baseline, PPO 에이전트 없음
- 5%: 전체 차량 중 일부를 PPO 에이전트로 제어
- 10%: PPO 에이전트 비율을 더 높인 조건

각 조건에서는 10개의 episode를 반복 실행하였고, episode마다 전체 차량 평균 속도, throughput, crash 여부를 기록하였다. 이번 평가에서는 모든 조건에서 crashed=0이 유지되었다.

2차 튜닝 후 평가 결과:
- 0%, 5%, 10% 모든 조건에서 crashed = 0
- 5%, 10% 조건에서 Baseline 대비 throughput 증가
- 10% 조건은 평균 속도를 거의 유지하면서 throughput 증가

15. 2차 튜닝 후 정량 결과​

2차 튜닝 후 평가 결과를 요약하면 다음과 같다.

침투율 0%
avg_speed 평균 ≈ 15.96
throughput 평균 ≈ 3.90
crashed 평균 = 0

침투율 5%
avg_speed 평균 ≈ 14.76
throughput 평균 ≈ 6.60
crashed 평균 = 0

침투율 10%
avg_speed 평균 ≈ 15.93
throughput 평균 ≈ 6.80
crashed 평균 = 0

Baseline과 비교하면, 5% 조건에서는 평균 속도가 다소 낮아졌지만 throughput은 증가하였다. 10% 조건에서는 평균 속도가 Baseline과 거의 유사하게 유지되면서 throughput이 크게 증가하였다.

5% PPO:
throughput 3.90 → 6.60
avg_speed 15.96 → 14.76

10% PPO:
throughput 3.90 → 6.80
avg_speed 15.96 → 15.93

특히 10% 조건은 평균 속도를 거의 희생하지 않으면서 통과 차량 수를 증가시켰기 때문에, 이번 2차 튜닝에서 가장 긍정적인 결과로 볼 수 있다.

16. 2차 튜닝 결과 시각화​

아래 그래프는 2차 튜닝 후 침투율별 평균 속도와 throughput을 시각화한 결과이다.

2차 튜닝 후 침투율별 전체 차량 평균 속도 비교

평균 속도 그래프를 보면, 5% 조건에서는 Baseline보다 낮은 평균 속도가 나타났지만, 10% 조건에서는 Baseline과 거의 유사한 수준의 평균 속도를 유지하였다. 이는 10% 조건에서 PPO 에이전트가 전체 차량 속도를 크게 떨어뜨리지 않으면서 교통 흐름에 개입했음을 의미한다.

2차 튜닝 후 침투율별 throughput 비교

throughput 그래프에서는 5%와 10% 조건 모두 Baseline보다 높은 값을 보였다. 특히 10% 조건에서는 throughput 평균이 Baseline 대비 크게 증가하였다. 이는 PPO 에이전트가 일정 비율 이상 투입되었을 때, 제한 시간 내에 더 많은 차량이 기준 지점을 통과할 수 있음을 보여준다.

17. Episode별 결과 분석​

침투율별 평균값만으로는 episode 간 변동성을 충분히 확인하기 어렵다. 따라서 각 episode에서 평균 속도와 throughput이 어떻게 변했는지도 함께 확인하였다.

2차 튜닝 후 episode별 평균 속도 변화

episode별 평균 속도를 보면, 각 침투율 조건에서 속도 값이 일정하게 유지되는 구간과 낮아지는 구간이 함께 나타난다. 특히 5% 조건에서는 일부 episode에서 평균 속도가 낮아지는 경향이 있어, throughput 증가와 평균 속도 유지 사이의 균형이 아직 완전히 안정화되지는 않았음을 확인할 수 있다.

2차 튜닝 후 episode별 throughput 변화

episode별 throughput 그래프에서는 5%와 10% 조건에서 Baseline보다 높은 throughput을 보이는 episode가 여러 번 나타났다. 다만 episode마다 throughput 편차가 존재하기 때문에, 현재 정책이 항상 안정적으로 높은 통행량을 보장한다고 보기는 어렵다.

따라서 이번 결과는 성능 개선 가능성을 확인한 결과로 해석하는 것이 적절하다.

18. 2차 튜닝 결과 해석​

2차 튜닝 후 결과는 다음과 같이 정리할 수 있다.

개선된 점:
- 모든 침투율 조건에서 crashed = 0 유지
- 5%, 10% 조건에서 throughput 증가
- 10% 조건에서 평균 속도 유지와 throughput 증가를 동시에 확인

아쉬운 점:
- 5% 조건에서는 평균 속도가 Baseline보다 낮아짐
- episode별 throughput 편차가 존재함
- 평균 속도 자체가 명확히 상승한 것은 아님

이번 추가 학습은 평균 속도 향상보다는 throughput 개선에 더 강한 영향을 준 것으로 보인다. 특히 10% 침투율 조건에서는 평균 속도를 거의 유지하면서 통과 차량 수가 증가했기 때문에, PPO 에이전트가 혼합 교통 환경에서 일정 수준의 교통 처리량 개선 효과를 만들 수 있음을 확인하였다.

다만 5% 조건에서는 평균 속도가 낮아지는 문제가 남아 있다. 이는 PPO 에이전트가 소수만 투입되었을 때는 전체 흐름을 충분히 조정하지 못하거나, 일부 episode에서 보수적인 주행 정책을 선택했을 가능성을 보여준다.

19. 결론 및 다음 개선 방향​

이번 2차 튜닝을 통해 PPO 에이전트의 침투율별 평가 파이프라인이 정상적으로 동작함을 확인하였고, 5%, 10% 조건에서 Baseline보다 높은 throughput을 얻을 수 있었다. 특히 10% 조건에서는 평균 속도를 거의 유지하면서 throughput이 증가하여, 추가 학습과 보상 함수 튜닝이 실제 성능 개선으로 이어질 수 있음을 확인하였다.

그러나 현재 정책이 완전히 안정적으로 수렴했다고 보기는 어렵다. 평균 속도 개선은 아직 제한적이며, episode별 throughput 편차도 남아 있다. 따라서 다음 단계에서는 평균 속도 저하를 줄이고, episode 간 성능 편차를 줄이는 방향으로 추가적인 학습과 평가가 필요하다.

다음 개선 방향:
- 평균 속도 보상 추가 강화 여부 검토
- throughput 증가와 속도 유지 간 균형 조정
- 5%, 10% 조건에서 episode별 편차 감소
- 더 긴 학습 step으로 재평가
- 다중 PPO 에이전트 학습 구조 검토

이번 결과를 최종적으로 정리하면 다음과 같다.

2차 튜닝 결과:
충돌 안정성 유지 성공
throughput 개선 확인
